# Changelog — list-active-reminders

## list-active-reminders — /list command: переглянути та скасувати заплановані нагадування

**What:** власник бота тепер може в будь-який момент набрати `/list` (або вибрати команду з меню) і отримати одне повідомлення зі списком усіх активних (`pending`) нагадувань, впорядкованих за часом спрацьовування від найближчого до найдальшого. Кожен рядок має дві inline-кнопки: **скасувати** (знімає нагадування до того, як воно спрацює) та **до джерела** (відкриває оригінальне повідомлення або показує його зміст inline, якщо немає публічного посилання). Якщо активних нагадувань немає — бот відповідає однозначним «немає активних нагадувань».

**Why:** до цього фічу бот був повністю реактивним: нагадування ставилось, зникало з поля зору і з'являлось лише у момент спрацьовування. Власник не мав способу перевірити, що зараз заплановано, і не міг скасувати щось непотрібне до спрацьовування. Це усуває зазначену прогалину — найнижчі витрати з найвищою цінністю після основного циклу capture→fire→resolve. Детально: [spec](./spec.md) §1–§2.

Ключові архітектурні рішення:
- [ADR-0001](./adr/0001-reuse-deleted-state-for-cancel.md) — скасування через наявний `deleted`-стан замість нового `cancelled`; схема та міграції не змінюються.
- [ADR-0002](./adr/0002-immutable-snapshot-list.md) — список — незмінний знімок у момент рендерингу; повторний натиск на скасоване нагадування є безпечним no-op.
- [ADR-0003](./adr/0003-single-message-overflow-truncation.md) — при переповненні показуються найближчі нагадування + суфікс «… ще M»; строго одне повідомлення на виклик `/list`.

**How to use:**
- Набрати `/list` у чаті з ботом або вибрати команду з меню Telegram.
- Отримане повідомлення показує всі `pending`-нагадування з preview тексту (~100 символів першого рядка), часом спрацьовування у домашньому часовому поясі власника та кнопками «скасувати» / «до джерела» для кожного рядка.
- Натиск «скасувати» — переводить нагадування у `deleted`, підтверджує окремим повідомленням, список залишається незмінним.
- Натиск на вже неактивне нагадування — безпечний no-op з повідомленням «більше не активне».

**Operational notes:**
- Migration: немає — читає існуючі таблиці `reminders` + `source_snapshots` через наявний індекс `idx_reminders_state_scheduled_at`; схема не змінюється.
- Feature flag / config: немає.
- Rollback: видалити код фічу та перезапустити бота; даних для відкату немає (жодних нових рядків чи колонок).
